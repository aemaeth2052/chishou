# ETC利用明細ダウンローダー

ETC利用照会サービス（https://www.etc-meisai.jp/）から、登録している全ETCカード（車両）の
利用明細PDFを、期間指定でまとめてダウンロードするWindows用ツール。

## 前提・注意事項

- **ETC利用照会サービスの[利用規約](https://www.etc-meisai.jp/rules.html)を必ず確認すること。**
  自動アクセスに関する制限がある場合、本ツールの利用はアカウント停止等のリスクを伴う。
  自社カードの明細を自社業務のために取得する用途を想定している。
- 公式APIは存在しないため、ブラウザ（Chromium）を自動操作する方式。
  **サイト側の画面変更があると動かなくなる**ことがある（後述のトラブル対応を参照）。
- ログインIDは1つ、そのIDに複数のETCカードが登録されている構成を想定。
- パスワードを保存する場合、`config.json` に**平文**で保存される。
  PC自体のログインパスワード・ディスク暗号化（BitLocker等）で保護すること。

## セットアップ（初回のみ）

1. [Python](https://www.python.org/downloads/) をインストール
   （インストーラーで「**Add python.exe to PATH**」にチェックを入れる）
   ※Microsoft Store版のPythonでも動作します。
2. このフォルダの `setup.bat` をダブルクリック
   （ライブラリとブラウザ(Chromium)のダウンロードが自動で行われる。5分程度）

> **補足:** 仮想環境(venv)は使わず、お使いのPythonに直接インストールします。
> Microsoft Store版PythonでvenvがうまくいかないPCでも動くようにするためです。

## 使い方

画面は上から「検索期間 → 検索対象 → 登録済み車両 → Hks番割から取込 → 実行」の順。
日常運用ではこの上から順に触っていけばよい（ID・パスワードは初回のみ「設定」タブで入力）。

1. `run.bat` をダブルクリックして起動
2. **検索期間**を指定（「今月」「先月」「昨日」で一発入力可。**過去62日以内**のみ）
3. **検索対象**を選択
   - **登録済みリストから複数選択** … よく使うパターン
   - **単一車両を指定** … その場限りで1台だけ調べたいとき
4. （リストモードの場合）車両を選ぶ
   - 一覧の「対象」列をクリックでチェックON/OFF
   - 並び順は列タイトルクリックで切替可
   - 新規登録は「設定」タブ（車両番号は必須、**備考**は任意・空欄可）。変更は **削除→再登録**
5. （必要なら）**Hks番割から取込**で顧客・現場・運転手を反映（→ Hks原価システム連携）
6. PDF保存先フォルダを確認して「実行」（ログイン情報は「設定」タブで事前に入力）

ファイル名は `日付_車両番号.pdf` 形式。

| ケース | 例 |
|---|---|
| 期間が1日のみ | `20260610_1499.pdf` |
| 期間が複数日 | `20260601-20260611_1499.pdf` |

期間内に利用がない車両はスキップされる。

## Hks原価システム連携

メインタブの「**Hks番割から取込**」ボタンで、起動中のHks「番割予定表」ウィンドウから
車両番号→顧客・現場の対応を読み取る（UI Automation。Hksと同じPCで実行すること）。

取込済みの状態で実行すると:

- **PDFファイル名**に顧客・現場が付く: `20260612_1499_株式会社フルハシ商事_出光興産千葉.pdf`
- **按分レポート** `按分レポート_期間.csv` に顧客・現場・通行料金合計が記録される

番割予定表が複数開いている場合は選択画面が出る。**取り込めるのは同じ日付の番割だけ**で、
異なる日付を同時に選ぶとエラーになる（誤作動防止）。検索期間が単日のときは、
**その日付の番割が自動でチェックされた状態**で表示される（違う日付は初期状態では未チェック）。

同一現場に複数車両が割り当てられている場合、運転手は特定できないため**空欄**にする
（顧客名・現場名は各車両に同じものが入る）。

取込内容は config に保存され、次回起動時も維持される（番割は日替わりなので、
**ダウンロード対象日の番割を表示した状態で取り込む**こと）。

## 運用向け機能

- **同名ファイルの扱い**: 「設定」タブで「連番を付ける(既定)/上書き/スキップ」を選択
- **失敗時の自動リトライ**: 1台失敗しても残りの車両を処理し、最後に失敗分だけ1回リトライ
- **実行サマリと履歴**: 実行終了時に「保存◯台/利用なし◯台/失敗◯台」を表示し、
  全件の結果を `logs/history.csv`(Excelで開ける)に記録
- **車両リストの受け渡し**: 「設定」タブからCSVで書き出し/読み込み。
  別PCへの配布時や、Excelでの一括作成に使う（形式: ヘッダ行`備考,車両番号`）

## 画面テーマ

UIは [ttkbootstrap](https://ttkbootstrap.readthedocs.io/) でモダンテーマ(cosmo)を適用している。
ttkbootstrap が入っていない環境でも、標準の見た目で問題なく動作する。
**更新後は `setup.bat` を再実行**するとライブラリが揃う。

## うまく動かないとき

エラーが出ると `logs/error_日時/` フォルダに**その時の画面のスクリーンショットとHTML**が
自動保存される。これを開発者（Claude）に渡せば、画面構成の変化に合わせて
`downloader.py` の `SELECTORS`（画面部品の定義）を修正できる。

よくある原因:

| 症状 | 対処 |
|---|---|
| 「画面部品が見つかりません」 | サイトの画面変更。logs の内容を添えて修正依頼 |
| 「ログインに失敗しました」 | ID/パスワードの確認。サイトに直接ログインして試す |
| ブラウザがすぐ閉じる・403 | サイト側のbot対策の可能性。「ブラウザの動きを表示する」をONで再実行 |

## 作業員稼働率の集計（番割 × 社員名簿）

番割（全作業員）と社員名簿CSVを突き合わせ、**営業所ごとの作業員稼働率**を出す補助ツール。
開いている番割が複数（例: 5営業所）あれば、(営業所, 日付)ごとに別々に集計する。

```
分母   = 出勤 ＋ 休み・待機         （＝在籍 − 事務所スタッフ等で番割に出ない人）
分子   = そのうち外貨を産む現場に出た人
稼働率 = 分子 ÷ 分母
```

- **出勤** … 番割に名前のある自営業所社員（名簿に照合できた人）
- **休み・待機** … 現場作業員で番割に名前がない人（分母に算入）
- **事務所スタッフ等** … 事務・ダミー登録など、**番割に出なければ分母に数えない**人。
  名簿CSVには判別フラグが無いので、`utilization_settings.json` の `non_field_staff`
  （社員コード or 氏名）で指定する。番割に名前が出た日はその人も分母に入る。
- 計上は**名簿に照合できた人のみ**。自社タグ付きでも名簿に無い人は計上せず「確認推奨」に出る
  （対照表でコードを当てると次回から計上）。

### 区分の判定（確認済み）

番割では作業員の所属営業所が**氏名前のバッジ**（蘇我/若松/八幡/都賀/加曽利/宮崎 等）で
示される。各番割の見出しの営業所を「自営業所(home)」とし、バッジと名簿で3区分に分ける。

| 区分 | 条件 | 扱い |
|---|---|---|
| **自営業所** | バッジが自営業所 or バッジ無し&自営業所の名簿にマッチ | 稼働率の分母・分子 |
| **他営業所応援** | 自営業所以外の営業所バッジ | 別集計（借りた人工） |
| **集計対象外** | バッジ無し&自営業所の名簿に無い（他営業所の自前労務） | カウントしない |

**外貨を産む現場** = 顧客名に除外キーワード（既定 `第一元商` / `宮崎興業`）を含まない現場。
送迎応援・寮清掃などの管理費現場は分子から外す。

名簿は営業所ごとにCSVが分かれていてよい。各番割は見出しの営業所で**名簿の「営業所」列**を
照合して自動的に正しい名簿を使う。1営業所ぶんだけ渡せば、その営業所の番割にだけ正しく動く
（名簿が無い営業所の番割は警告を出す）。

### GUIで使う（おすすめ）

`utilization_app.bat` をダブルクリックすると稼働率アプリが開く。タブ構成:

| タブ | 役割 |
|---|---|
| **集計** | 名簿を指定 →「番割から集計する」→ 営業所ごとの稼働率を一覧表示。名簿の指定は記憶される |
| **除外設定** | 外貨を産まない顧客／現場のキーワード（部分一致）と、分母から除く事務所スタッフ（コード/氏名）を画面で編集・保存 |
| **対照表** | 取りこぼし候補を一覧表示。行を選び「自社／他営業所／対象外」を割り当て（推奨コードが自動入力）。`name_aliases.json` に保存される |
| **履歴** | `utilization_history.csv` の推移を表示 |

集計を押すと、レポート・明細・履歴・取りこぼしの各ファイルも自動で書き出される（CLIと同じ）。

### Googleスプレッドシート連携（サービスアカウント方式）

GUIの「Google連携」タブで設定すると、集計のたびに **(日付×営業所)** をスプレッドシートへ
**上書き/追記**（同じ日付・営業所は上書き）する。列は履歴CSVと同じ。

一度だけの準備:

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作成
2. 「APIとサービス」→ **Google Sheets API** を有効化
3. **サービスアカウント**を作成 → 鍵を **JSON** でダウンロード
4. 対象スプレッドシートを、そのサービスアカウントのメール
   （`xxxx@xxxx.iam.gserviceaccount.com`）に **編集者** で共有
5. アプリの「Google連携」タブに **JSONのパス** と **シートURL** を入れて「接続テスト」→「保存」、
   「集計時にスプレッドシートも更新する」にチェック

以降は「番割から集計する」を押すたびに、ローカルCSVと同時にシートも更新される。
JSONキーは資格情報なので、PC内で安全に保管すること（パスのみ設定に保存される）。

### CLIで使う

1. Hksから**社員名簿をCSVで書き出す**（コード,名称,フリガナ,営業所,区分,備考,…,在,… の形式。Shift-JIS）。
   営業所ごとに分かれていてよい
2. 名簿の置き方（どれか）:
   - **`roster` フォルダ**を同フォルダに作り、各営業所のCSVを入れる（中の `*.csv` を全部読む）← 5営業所はこれが楽
   - 1ファイルなら `roster.csv` として同フォルダに置く、または `utilization.bat` にドラッグ＆ドロップ
3. Hksの番割予定表を開いて実行（**複数営業所・複数日付を何枚開いてもよい**。全画面化は不要）
4. 出力:
   - `utilization_report.txt` … 営業所ごとの稼働率と内訳
   - `utilization_detail.csv` … 作業員ごとの判定明細（営業所・バッジ・区分付き。Excelで開ける）
   - `utilization_history.csv` … **日次履歴**（日付×営業所ごとに1行を追記。同じ日付・営業所は上書き）。
     Excelでピボット/折れ線にすれば日々の推移が見える
   - `utilization_review.csv` … **取りこぼし候補**（自社かもしれないのに対象外/名簿未照合の人）。
     - `確認推奨` … 自営業所タグ付きなのに名簿に無い＝ほぼ自社。`name_aliases.json` にコードを追記
     - `要確認` … カナ(外国人)・無バッジ・名簿外。自社の取りこぼしか他営業所自前かを目視で判断
     日本人フルネームは確実に一致するので、ここには出ない

### 日付・複数番割の扱い

集計は **(営業所, 日付) ごとに完全に独立**。番割を何枚開いても、見出しの営業所と日付で
仕分けて、それぞれ別の稼働率を出す。

- 5営業所ぶんを開く → 5本の稼働率（各営業所の名簿で判定）
- 同じ営業所で複数日付（今日・明日 等）を開く → **日付ごとに別々**に集計し、履歴も日付ごとに別行
- 同じ(営業所,日付)を二重に開いていても、人は名簿コードで重複排除される

### 貸出（他営業所へ）

自営業所から他営業所へ貸し出した作業員は、自営業所の番割に**自営業所タグ付き**で出る。
これは稼働（外貨）として算入したうえで、「**うち他営業所へ貸出 N名**」として内訳に表示する。
（他営業所→自営業所の応援は逆に「他営業所応援」として別集計）

### 例外（除外）キーワードの管理

外貨を産まない（管理費）現場の条件は **`utilization_settings.json`** で管理する。
`utilization_settings.example.json` をコピーして編集する。いずれも**部分一致**。

```json
{
  "exclude_customer_keywords": ["第一元商", "宮崎興業"],
  "exclude_site_keywords": ["送迎", "寮", "清掃"]
}
```

- `exclude_customer_keywords` … 顧客名にこの語を含む現場を管理費（分子から除外）
- `exclude_site_keywords` … 現場名にこの語を含む現場を管理費

検証用に、番割を読まず `inspect_workers.py` の出力から再計算もできる:
`python utilization.py --roster roster.csv --inspect workers_inspect.txt`

### 突合の精度と補正

日本人はフルネームで自動一致する。外国人は番割が**短縮ニックネーム表示**のことがあり、
名簿（フルネーム）と機械一致しない場合がある。取りこぼしは `name_aliases.json`
（番割表示名 → 名簿コード／`"other"`(他営業所)／`"ignore"`(対象外)）で個別に補正する。
書式は `name_aliases.example.json` を参照。

> **判別軸は氏名前の営業所バッジ**。背景色での判別は不可（番割の濃淡ノイズを拾うだけで
> 自/他/応援を分けられない）。●★の印も区分を分けていない。
